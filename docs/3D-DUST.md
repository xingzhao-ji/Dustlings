# Dust that can be seen and removed

Status: one candidate ready for integration, awaiting final integrated visual review and human validation. No target-player or owner acceptance is recorded. This is courtyard feedback only; it changes no cleaning amount, reachable surface, collision, progression or creature design.

The concrete problem came from the independent development critic: untouched brown paving could look like clean stone, and brushing could read as polishing. The smallest proposed correction adds irregular, very low powder drifts and thin bent fibres on existing paver faces, then lets the same live dust field remove them. Short brushing wisps occur only when actual dust is removed. The benefit is a clearer dirty → clean transformation and a small tactile response. Whether the new marks read as dust remains an aesthetic hypothesis; no preference or enjoyment score is claimed.

## Integration contract

`DustFeedback` extends `Node3D` with no autonomous processing. Call `configure(field: ImageTexture, dust: Array)` before or after adding the node, then `tick(delta, elapsed, removed_brushed, world_point, gentle)` while gameplay is active. `removed_brushed` must be the actual amount removed since the previous call, not a held-button flag. Prefer the simulation's physics cadence. `reset()` clears transient wisps and direction/credit when loading or applying a fixture. The root retains and updates the existing 29 × 18 RF `ImageTexture`; the shader uses the same world mapping as the paving: origin (−7.25, −4.09), span (14.5, 8.64).

The component has four static MultiMesh batches (three low drift shapes and one fibre shape), 997 submitted instances in the current 492-cell courtyard, with a hard cap of 1,200. Brushing uses one extra MultiMesh with a cap of 32 wisps; gentle motion reduces the cap to 8, duration to 0.22 s and lift to 0.008 world units. There is no idle emission, collider, screen overlay, audio or shadow-casting geometry. The caller's pause freezes time. Static marks shrink with remaining dust and disappear below the field threshold. Fully restored surfaces retain the original paving geometry.

Fractional emission credit survives zero-removal frames for 0.2 s. This supports a 120 Hz render caller receiving 60 Hz simulation changes without repeatedly erasing half-earned credit. Zero-removal calls still cannot spawn a wisp, and the short grace expires stale direction and credit. Physics calls remain the intended integration.

## Actual review and bounded checks

The native comparison ran on 2026-09-10 with Godot 4.7.2, Metal Forward+, Apple M4 Pro, a 1280 × 800 viewport, frozen copies of the current main/simulation and an isolated `--qa` profile. Ordinary progress was untouched. The [6.67-second recording](../evidence/3d/dust-feedback/motion.mp4) is a silent, controlled component fixture: brushing is accelerated threefold, then jumps to 50-helper and completed fixtures. It is not human input, a pacing test or an audio audition.

Normal-size still inspection found additional irregular powder marks, a visible cleared patch and no remaining marks on the completed paving. The root independently reviewed the normal-size after/brushed stills and accepted the candidate for integration. The marks may still read as mottled stone; this disagreement is unresolved. No benchmark-quality claim follows from the inspection.

The paused, matched opening snapshots measured 36 baseline draw calls and 40 with static dust. The 50-helper fixture measured 301 total draw calls; there was no matched 50-helper baseline in this run. These are draw-count snapshots, not sustained frame-rate evidence. Movie Maker's reported zero GPU time is unsupported and must not be interpreted as zero cost. Native rendering, fixture cleanup, no-collider checks, zero initial/settled emission, normal/gentle caps and reset passed without runtime errors. Raw [results](../evidence/3d/dust-feedback/render-results.json) and [log](../evidence/3d/dust-feedback/render.log) are preserved.

After that capture, two focused reliability corrections confined marks/moving wisp footprints inside flat paver faces and retained fractional credit across interleaved render frames. The palette is unchanged. The exact [post-render diff](../evidence/3d/dust-feedback/post-render-correction.diff) separates captured and final sources; the final integrated capture is still required. Headless checks of CPU-submitted mesh transforms found all static vertices inside flat faces, minimum height 0.001 and maximum 0.023604 world units. Alternating 120 Hz removal/no-removal calls produced up to 14 wisps; idle settled to zero, gentle cap stayed 8 and reset emptied the batch. [Final state results](../evidence/3d/dust-feedback/final-state-results.json) passed.

The first headless geometry assertion was an invalid GPU-readback probe: Dummy rendering returned identity for every MultiMesh transform. Its failure and identity diagnostic are preserved, not counted as passing. The corrected isolated subclass records transforms before submission and checks actual generated vertices; it does not claim GPU readback. Frozen fixtures, both candidate versions, the unchanged shader and SHA-256 hashes are in [the evidence directory](../evidence/3d/dust-feedback/).

## Remaining checks, in player-impact order

1. In the current integrated native build, unfamiliar players should identify the removable material as dust before instruction and distinguish brushed paths from untouched paving. Ask whether powder looks like decorative/mottled stone; test a focused alternative only if evidence warrants it.
2. Inspect the final grounding/cadence corrections in actual integrated brushing motion, including edges, fountain, 50 helpers and gentle motion. Look for apparent hovering, thin-fibre shimmer, camera-scale disappearance or obstruction of destinations. Current numerical bounds do not establish optical balance.
3. Measure sustained performance with the integrated candidate under the same 50-helper conditions as the root's baseline. Preserve frame-time observations and device/renderer details; this component's four static draw calls are not a performance guarantee.
4. Human feedback must judge brushing satisfaction, clarity of the dust-to-helper relationship and whether the restored paving feels rewarding. There have been zero such sessions on this candidate.

Exact next action: root integrates one configure call, one physics tick using actual removed dust and reset on load/fixtures; inspect the current build and rerun the bounded 50-helper profile. Do not change this palette or add more particles before that review.
