# Courtyard interaction and accessibility audit

This is a focused implementation audit, not a claim of accessibility conformance or a substitute for players using assistive technology. No screen reader was operated and no unfamiliar player participated. Chrome's accessibility tree, DOM mutations, and trusted browser input were inspected. Touch and viewport layouts were emulated; `document.hidden` was overridden only for the isolated background-handler check.

Reproduce with `node tools/accessibility-audit.mjs` while the local server runs at `http://127.0.0.1:4173`. The tool owns fresh isolated browser contexts and records `evidence/accessibility-audit.json`. Its restored states are test fixtures, not observations of player progress. Root gameplay captures/performance work may run concurrently; this audit reports functional outcomes, not performance or completion times.

The initial audit found 10 failed checks across seven related issue groups, plus five passing checks. After Root integrated the focused fixes and keyboard controller, the current audit passes all 20 checks with zero uncaught browser errors. The JSON is the source for the latest rerun status; the findings below preserve the original evidence and acceptance checks. This passing implementation audit does not establish full screen-reader access or comfortable keyboard play for human players.

## Passing recovery and audio checks

- Opening Settings pauses and suspends audio.
- Importing a damaged JSON file keeps the current dust state and displays a recovery error.
- Importing a valid partially restored state restores 400 cleaned units and 40% restoration; the audio progress follows that stage while remaining paused in Settings. The fixture exceeds the required 75% cleanup threshold for fountain progress.
- A corrupt primary save recovers the valid backup and explains that recovery in the welcome flow.
- When the `localStorage` property itself throws, the game remains playable, explains unavailable saving, and exports a valid save file containing 466 dust entries.

The existing browser interaction suite separately covers pointer cancellation, tap-sweep cancellation, 42 px touch offset, visible direct preview, blocked destinations, exact reload progress, persisted settings, native modal focus, drawer operation, zoom/pan mapping, and portrait/landscape overflow. Those checks do not establish legibility, comfort, reachability with assistive input, or sound quality for intended players.

## Keyboard implementation checkpoint

`src/keyboard.js` exports `createKeyboardControls({canvas,getState,renderer,onMode,onAssign,onPan,onNotice,onChange})`. It installs no document listeners. Root routes `handleKeyDown` / `handleKeyUp`, calls `update(dt)` immediately before simulation, and calls `stop()` on focus interruption, modal opening, pointer use, and tool switches. A handled key returns true so Root can prevent its browser default.

With canvas focus, arrows move the visible world cursor; Space toggles brushing; N selects a nearby remaining patch; Enter assigns in Direct mode; Shift+arrows pans. New explicit N/Space actions produce a concise notice, while holding movement does not create repeated announcements. Cursor movement and N request camera adjustment through `onPan` if the cursor reaches the visible field edge. Space ignores key repeat, and keyboard focus loss stops brushing and held movement. Repeated Space toggling and N navigation reduce the need to hold a key continuously; comfort remains a player-test hypothesis.

Four focused simulation tests in `tests/keyboard.test.mjs` pass, covering keyboard-driven dust collection through first helper and meaningful upgrade, crew assignment, ignored Space repeats, focus interruption, cursor bounds, Shift-pan delegation, and announcement restraint.

The integrated browser audit now uses real N, arrow, Space, D, Enter, and Tab key events to aim a visible cursor, collect dust, stop brushing, assign the crew, and buy A softer sweep through keyboard focus. It explicitly advances 50 simulation seconds between keyboard actions, producing four helpers and 33 motes; the first helper appeared around 8.5 simulated seconds. Tab reaches the affordable upgrade after the tool, free-roam, and camera controls. Space stopping preserved the manual-brushing statistic exactly. These are synthetic execution observations, not human pacing or usability results. The save call is awaited where a check depends on completion of its Web Lock transaction.
