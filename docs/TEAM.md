# Dustlings development roles

The lead developer (root) owns the integrated playable game, coherent art/interaction direction, source freezes, package verification and continuation checkpoints. User vision and scope govern all assignments: Windows Steam first, Mac checks throughout, later mobile ports; original cozy restoration in one three-zone village; courtyard first; Sky atmosphere/cohesion reference; current-build human and owner acceptance remain mandatory.

Specialists receive a bounded task, player benefit, concrete evidence, file ownership and observable acceptance. Recent independent work covers native lifecycle/recovery, UI sound, storefront requirements, native icons and an isolated lighting/framing comparison. Shared runtime edits are integrated by the lead; isolated candidates are inspected in actual gameplay before use. Available concurrency is four agents including the lead; use only useful parallel work.

The independent critic is separate from development. It owns `docs/CRITIQUE-0.3.md` and `evidence/v0.3/critic/`; developers do not write or revise its verdict, set an approval target, or pressure it to approve. It receives the integrated build and the same vision, then reports consequential weaknesses and positives with evidence. The lead verifies claims, assigns focused corrections, integrates them and requests another review of the changed build where warranted.

The critique agent is an AI reviewer. Its observations and aesthetic hypotheses are not representative human playtests, market evidence, or owner approval. Its review discloses any prior documentation, fixtures, automation or runtime limits. Human sessions remain0. Participant segments and n/N requirements in PLAYTEST.md remain independent of this development process.
